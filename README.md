# Lit RPG

A practical playbook for writing LitRPG novels, then adapting them for Pocket FM when requested. It combines original working methods, a carefully labeled study of the supplied sources, reusable prompts, and examples.

## Use this in a new chat

Paste this message with the repository link:

> Read https://github.com/Chronomanga/Lit-RPG/blob/main/START-HERE.md and follow its reading order. Use this repository as the writing workflow. Tell me which files you actually read. Begin Step 1 for my new LitRPG novel, and complete only that step before we review it. My idea is: [idea].

For an existing story, replace the final two sentences with:

> Continue my existing project at its current step. First read its latest manuscript, authoritative canon, and handoff. Do not restart, silently change established facts, or assume this repository contains my project's current state.

The repository is reusable context, not permanent model training. A future assistant must actually read it, and must report access problems. The repository does not guarantee a particular model's work or replace the owner's decisions.

## The process

1. Define the story's promise and scope.
2. Build the protagonist, companions, and opposing force.
3. Design the System and its rules.
4. Build the world shaped by those rules.
5. Plan meaningful progression.
6. Outline the book's arc and resolution.
7. Design the opening.
8. Make chapter cards.
9. Draft a chapter.
10. Audit and revise it.
11. Complete and review the book.
12. Adapt it for Pocket FM when requested.

Use one step at a time by default. If the owner requests a complete episode, chapter, or batch, finish that authorized piece and its necessary revisions without interrupting for routine approvals. Before each next episode, read the same persistent Excel workbook and latest confirmed actual ending. After full prose, revision, and a final read, update its existing sheets with actual facts, source/version or hash, affected checks, stopping point, and review status; verify before continuing. Preserve history and notes. Do not create a new workbook or sheets per episode. Follow the required loop in [CONTINUITY.md](CONTINUITY.md).
